You convert the formatted timetable text below into ONE JSON file for the Medscope Timetable
Studio tool. The text is the only source. Copy everything exactly: do not add, correct, shorten

## How to read the text
- Header lines "📌 {Module} | {Term} | {Year}" and "📌 Group (X) - Section N (practical group
  N)" give module title, term, year, group letter and section numbers.
- 🦅 = week, 🔷 = day (day/month), 🔹 = session type and number, 👉 = subject, ( ... ) lines =
  topics, then the ( time ) line with the place. "off" = no session.
- Times are 12-hour without am/pm: 8, 9, 10, 11 are morning, 12 is noon, 1 to 7 are afternoon
  (add 12): 12:30 - 2 = 12:30 to 14:00. Write times as HH:MM.
- Year comes from the header; dates become YYYY-MM-DD. If a date's real weekday does not match
  the day name in the text, keep the date and list it in Discrepancies.

## JSON rules
- "module": {"title", "term", "weekdays": ["Sat","Sun","Mon","Tue","Wed","Thu"]}.
- "sections": {"id":"4","letter":"B","number":4,"practicalGroup":4,"label":"Group (B) Section 4"}
  for each section in the text (id = the section number as a string).
- Types: Tutorial = "tut", Lecture or Lec. = "lec", Practical = "prac". For any other type in
  the text, add it to "sessionTypes" with a short new lowercase key and its label, and mention
  it in Discrepancies. "sessionTypes": [{"key":"tut","label":"Tut."},{"key":"prac","label":
  "Practical."},{"key":"lec","label":"Lec."}] plus any new ones.
- "number": the number written after the type ("Tutorial 2" = 2, "Lec. 21" = 21). If none is
  written, OMIT "number". Never invent one.
- "subject": the text after 👉 with a trailing counter number removed ("Anatomy 1" becomes
  "Anatomy", "Histology 9" becomes "Histology"). Keep everything else exactly, including
  capital letters ("RADIOLOGY" stays "RADIOLOGY").
- "subjects": one entry per distinct subject with color: Anatomy #a01040, Histology #f0b0d0,
  Physiology #90f0e0, Biochemistry #c0f080 (match ignoring capital letters); any other
  subject #d9d9d9.
- "topics": one array entry per topic line, without the parentheses, exactly as written.
- "weeks": [{"n":1,"days":[...],"sessions":[...]}].
  "days" lists EVERY day that appears under that week in the text (every 🔷 line, including
  days marked off), as YYYY-MM-DD dates in order. Never leave a day out, never add a day that
  is not in the text.
  Session fields: date, type, number (if any), subject, topics, scope, start, end, place,
  status ("normal" or "recorded"), note ("").
- Recorded: status "recorded", start "", end "", place "". A day marked off has no session but
  still appears in "days".
- Scope: {"sections":["4","5","6"]}. If several sections in the text have the SAME date, type,
  number, subject, topics, time and place, write ONE session listing all of them. If anything
  differs, even only the time, write separate sessions.

every 🔷 day in the text is in its week's "days"; every session date is inside its week's
"days"; no section has two overlapping normal sessions; the JSON is valid.
